# Storybook Design Guide

Storybook UI is a work surface, not a marketing page. Studio is dense and
review-oriented; Play is reading-oriented and keeps authoring controls out of
the player path.

## Surfaces

- Studio groups source intake, foundation review, playtest, promotion, and
  advanced governance controls.
- Play presents the current scene, available choices, run state, and recoverable
  failure surfaces.
- AI Config appears as app settings infrastructure and uses Kit/Nimi SDK
  surfaces instead of app-local provider controls.

## Interaction Tone

- Validation failures are explicit and typed.
- Missing Runtime, missing AI Config binding, or incomplete truth never becomes
  success copy.
- Controls are compact and operational; explanatory copy stays close to the
  affected state.
